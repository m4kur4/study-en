# 設計

この文書は、仕様をどの仕組みで実現するかである。学習者ごとの表現一覧は含まない。

## 思想

毎回の意味調べは、短い規則だけで処理する。待ち時間を増やす専門家は、詳しく、クイズ、声に出して、会話練習のときだけ使う。専門家は読み取り専用で、ファイルは親が更新する。

毎回プロンプトに載せる規則は三つで、それぞれ50行以内にする。

- `english-study` は手順である。
- `english-quality` は、場面を誤らないこと、どういたしましてとこちらこそを分けること、壊れた疑問文を残さないこと、発音を根拠なく別の単語にしないこと、音のつながりは気を付ける点だけ短く足すことである。
- `public-repo-privacy` は公開前の原則である。学習手順より優先する。

復元の細かい手順と commit メッセージは `notebook-maintain` スキルに置く。出題の読み方は `english-quiz` スキルに置く。通常の意味調べでは読まない。検査の一覧は規則へ書き戻さず、スクリプトが判定する。

チャットのたびに全体は検査しない。`notes/optimize.md` の最終チャットが日本時間の今日より前のときだけ、`scripts/check-notebook.ps1` のあと `scripts/check-setup.ps1` を実行する。失敗したらノートを更新しない。`setup:` は設定の不足である。破損としての復元はしない。`fix:` の手順を先に提案する。仮のマスク行と、頼まれていない表現は作らない。clone 後にユーザーが行う手順は `Readme.md` に書く。

表現は1件1ファイルにする。1件を直すときに隣の表現まで書き換わらないようにするためである。質問のたびに全ファイルは開かない。同じ見出しは索引だけで判断する。同じ表現のまとめは、日付をまたいだ最適化で索引の行だけを見る。

公開した履歴は、force push なしでは消えない。マスクの抜けを、あとから push で取り消す前提にはしない。形で判定できるものと、非公開文字列の一覧は、commit の前にスクリプトが止める。エージェントがスクリプトを忘れたときも、Git の pre-commit が同じ検査で commit を拒否する。

clone では `.git/hooks/` は届かない。届くのは `scripts/git-hooks/pre-commit` と `scripts/install-hook.ps1` である。新しい環境では、起動ファイルを LF で作り直す。

## 意味調べ

1. `notes/optimize.md` の最終チャットが日本時間の今日と同じなら、全体検査も索引合わせも出題の作り直しもせず、見出しの検索へ進む。
2. 今日より前なら、`scripts/check-notebook.ps1` と `scripts/check-setup.ps1` を実行する。失敗したらノートを更新しない。通過したら、未処理の日次ログに無い索引行だけを足す。今日のログは対象にしない。索引の日付を前日にする。続けて、索引の行だけで同じ表現を1件にまとめる。近いだけの別表現はまとめない。過去の文は読み直さない。質問のたびには、この全体の比較はしない。
3. 続けて `scripts/build-quiz.ps1` を実行する。成功したときだけ、クイズの日付と最終チャットの日付を今日にする。失敗したときは両方を進めず、次のチャットでやり直す。
4. 索引の見出しを検索し、一致した1ファイル、または今から作る1ファイルだけを開く。
5. 英語を先に、和訳を直下に返す。保存するのは要約である。「What does the next sentence say?」または「What's the next sentence saying?」のあとに文があるときは、和訳のあとに、かたまりごとの役割を短く足す。構造は回答だけにし、ノートには書かない。残すのは、その文から取り出した単語や言い回しである。複数あればそれぞれ1件にする。取り出せなければ何も残さない。機能語だけと、文全体は残さない。`## 例` には、その表現を使った短い英文を1つ書く。元の長い文は、そのまま例にしない。例が既にあれば足さない。文そのものは、残すと言われたときだけ一度きりのまとめへ置く。ニュアンスや類似表現があれば、そのあとへ短く足し、要約にも残す。無いときは足さない。例文のあと、音のつながりで気を付ける点があれば一つか二つ短く足す。無いときは足さない。文全体のつながりは回答だけにし、ノートには書かない。表現そのものにいつもあるつながりは `## 発音` に短く書く。一般的な言い方でない文は、残すかどうかを意味の回答の中で確認し、認められるまで保存しない。日本語を英語にするにはどうすればよいか、という質問は保存しない。索引を見ること、検査を省くこと、何を残す予定かは、作業の前に書かない。意味の回答は一度だけ出す。
6. 対応の最後に、日付を進めたか、直前の commit から1時間以上たっているときだけ commit する。成功したら origin へ push する。

## 出題ファイル

`scripts/build-quiz.ps1` が日次ログの phrase 行を集め、索引でパスと日本語を引く。重複する見出しは1回にする。100件を上限に無作為へ選ぶ。100件に満たないときは、あるもの全部である。表現ファイルの本文は開かない。結果は `notes/quiz.md` へ上書きする。各項目はパス、日本語、`done: no` である。英語の見出しは書かない。

ユーザーが「クイズして」と言ったとき、スキルは `done: no` から1件を無作為に選び、日本語だけを出す。正解した項目だけ `done: yes` にする。不正解は残す。未回答が無くなったら、同じスクリプトで100件を作り直す。この作り直しは、日付をまたいだ最適化とは別に行い、`notes/optimize.md` の日付は進めない。パスは、答えたあとで表現ファイルを開くために使う。

## 復習HTML

`scripts/build-review.ps1 -Date yyyy-MM-dd` が、その日の日次ログを `review/YYYY-MM-DD.html` へ上書きする。カードの欄は、英語の見出し、場面、意味、例、発音の順で、欄は省かない。発音が無いときは空欄のままである。クイズとは別で、`notes/optimize.md` の日付は進めない。ユーザーが日付を指定したときだけ実行する。

## 公開と commit

`scripts/scan-public.ps1` は、非公開文字列のファイルが空なら失敗する。ステージした差分、または origin に無い commit の差分から、メールアドレス、電話番号、長い桁の番号、秘密鍵、トークン、ユーザープロファイルを含むパス、長い ID 付き URL、一覧にある文字列を探す。出力は種別とファイル名だけである。

Git の pre-commit は、リポジトリ内の `scripts/git-hooks/pre-commit` を sh で実行する。`.git/hooks/pre-commit` はその1行を呼ぶ起動ファイルである。初期化時に BOM なし UTF-8、改行 LF だけで書く。`Set-Content` と `Out-File` は使わない。CR があれば起動ファイルを消し、検査は失敗にする。

Cursor の `beforeShellExecution` は、`git commit` と `git push` の前に同じ検査を実行する。`--no-verify`、`--force`、push の `-f`、`core.hooksPath` は拒否する。`sessionStart` では検査結果を会話へ足さない。

最初の commit と push は、ユーザーが `notes/private-mask.txt` へ文字列を書き、そのあとで指示したときだけ行う。仮の1行は書かない。

## 破損

破損は、Git のオブジェクトが壊れているときと、索引と表現ファイルの対応が崩れているときである。意味が弱いだけでは破損にしない。

検査が失敗したあとはノートを変更しない。`git fsck` が失敗しているときは戻さない。それ以外は、ユーザーの確認のあと、失敗したファイルだけを健全な commit から戻す。全体を戻すときは、捨てるファイル名を示して再確認する。戻したあとも force push はしない。

## 別環境

clone のあと、エージェントは `docs/reproduce-prompt.md` の手順で起動ファイルと空の `notes/private-mask.txt` を用意する。追跡される規則、スキル、スクリプトは clone に含まれる。origin は clone が持つものを使う。新しい remote は、ユーザーが指示するまで足さない。
