# 仕様

この文書は、英語学習ノートを別の環境へ移すための仕様である。学習者ごとの表現一覧は含まない。

## 想定する使い方

このフォルダを Agent モードのチャットを一つだけ開いて使う。質問は、チャットのマイクで話した英語か、入力欄へ直接書いた日本語または英語である。マイクは書き起こしを質問文にする。答えはテキストで返り、読み上げはしない。書き起こしを見てから送信する。マイクを止めただけでは送信しない。

通常の質問には、自然な英語を先に、その直下に和訳を返す。英語は2〜4文で、例文は1回だけである。同じ文を復唱用に繰り返さない。例文のあと、音のつながりで気を付ける点があれば一つか二つ短く足す。無いときは足さない。文全体のつながりは回答だけにし、ノートには書かない。表現そのものにいつもあるつながりは `## 発音` に短く書く。「What does the next sentence say?」または「What's the next sentence saying?」のあとに文があるときは、その文の和訳に続けて構造を短く示す。文を数個のかたまりに分け、各かたまりの役割を日本語で書く。意味が変わる点は一つか二つである。品詞の講義にはしない。構造は回答だけにし、ノートには書かない。ニュアンスや、その場で使える類似表現があれば、回答のあとに短く足す。無いときは足さない。質問の回答では、ノート全体から近い見出しは探さない。残す要約には、答えた補足があれば短く入れる。クイズの出題中だけは日本語だけを見せ、ユーザーが答えたあとで英語と和訳を見せる。出題のチャットには、ファイルパスも英語も出さない。

文から残すのは、人が使う単語や言い回しである。複数あればそれぞれ1件にする。索引の見出しと照合し、一致したファイルだけを開く。無ければその表現のファイルを作る。日次ログの見出しもその表現にする。取り出せなければ何も残さず、そのことを意味の回答の中で一言伝える。機能語だけと、文全体は残さない。`## 例` には、その表現を使った短い英文を1つ書く。元の長い文は、そのまま例にしない。例が既にあれば足さない。作業の前に、索引を見ることや検査を省くことは書かない。意味の回答は一度だけ出し、同じ内容を繰り返さない。文そのものは、残すと言われたときだけ一度きりのまとめへ置く。過去の文は読み直して分解しない。聞き方の型は別ファイルへ置く。残すのは質問の原文ではなく、見出しと、意味と用法の短い要約である。「メモしないで」と言われた質問は保存しない。学習法の話は保存しない。日本語を英語にするにはどうすればよいか、という質問も保存しない。

同じ英語の見出しが既にあれば、新しいファイルは作らない。そのファイルだけを開き、要約に無い用法のときだけ更新する。同じ表現を指す見出しのゆれは、日付をまたいだ最適化で、索引の行だけを見て1件にまとめる。質問のたびには全体を見ない。近いだけの別表現はまとめない。

「この意味は違う」と言われたときだけ、その1件の要約を直す。書き起こしが語として壊れているとき、または聞き慣れた句と一音だけずれているときだけ、保存の前に確認する。直接入力した文は確認しない。一般的な言い方でない文は、残すかどうかを確認し、認められるまで保存しない。

「詳しく」「クイズして」「声に出して」「会話練習」のときだけ、英語の専門家を使う。日付や出典を指定したクイズは、その日次ログから1件出す。指定が無い「クイズして」は、出題ファイルの未回答から1件出す。正解した項目は、そのファイルを作り直すまで出さない。未回答が無くなったら、過去のログから100件を作り直す。

指定した日付のノートのサマリを HTML にするときは、その日の日次ログだけを同じカード型の `review/YYYY-MM-DD.html` にする。クイズとは別である。日付が無いときは今日と決めない。スクリプト以外では HTML を書かない。日付をまたいだ最適化では、日本時間の前日のログがあるとき、同じスクリプトでその HTML も作る。

日付をまたいだ最初のチャットで、先にノート全体の検査と設定の不足を見る。失敗したらノートは更新しない。通過したら、前日までの索引を揃え、同じ表現の索引行を1件にまとめ、出題ファイルを100件まで作り直し、前日のログがあればその復習 HTML を作る。同じ日の質問では、この検査も索引全体の比較も出題の作り直しも前日の復習 HTML もしない。未回答が尽きたあとの作り直しは、この日付の更新とは別であり、復習 HTML は作らない。commit は、その作業で日付を進めたとき、または直前の commit から1時間以上たっているときだけ、変更があれば1回作る。成功したら、既存の origin へ push する。最初の commit と push は、ユーザーが非公開文字列を書き終えて指示するまで行わない。

## 内部的な管理方法

日付は日本時間である。

- `notes/phrases/` は再利用できる表現。1見出し1ファイル。必須の見出しは `# 見出し`、`## 意味`、`## 例`。`## 場面` は casual、neutral、formal のいずれか。
- `notes/once/` は、残すと言われた文だけを日付ごとに1ファイルへまとめる。通常のクイズには出さない。過去の文から表現は抽出しない。
- `notes/ask.md` は聞き方の型。日次ログにもクイズにも入れない。
- `notes/index.md` は重複確認で読む行である。本文は読まない。1行は `path | heading | register | ja | kind`。kind は phrase か once。
- `notes/log/YYYY-MM-DD.md` はその日に扱った見出しだけである。1行は `heading | kind | source | status`。status は new か update。本文は書かない。
- `notes/quiz.md` は事前に集めた出題である。1件はパス、日本語、`done` である。`done` は `no` か `yes`。英語の見出しは書かない。日本語は索引の行から取る。上限は100件である。
- `review/YYYY-MM-DD.html` は、その日の復習である。クイズの出題ファイルとは別である。`scripts/build-review.ps1` だけが、その1ファイルを上書きする。ユーザーが日付を指定したときは最適化の日付を進めない。日付をまたいだ最適化では、日本時間の前日のログがあるとき同じスクリプトを実行し、成功したときだけクイズと最終チャットの日付を進める。ログが無い前日は作らない。
- `notes/optimize.md` は三つの日付を持つ。`索引` は索引を揃えた最後の日。`クイズ` は出題ファイルを作った日。`最終チャット` は、その作業を最後に行った日。
- `notes/private-mask.txt` は公開したくない文字列を1行ずつ書く。`#` で始まる行と空行はコメントである。このファイルは commit しない。空のあいだは commit できない。

索引の検索は見出しの一致だけである。その文から取り出した言い回し以外の表現ファイルを変えたら、commit せずに知らせる。対応の開始前から変更されていたファイルは、この件数に入れない。
